## 1. CRITICAL + HIGH findings

### C1 — Export libraries ship in the main invoice bundle (856 KB chunk)
`lib/invoice/export.ts:1,8,9` statically imports `html2canvas`, `docx`, and `jspdf`. `app/page.tsx:18` imports that module eagerly. **Measured:** all three land in a single **856 KB** chunk (`0_zyzy3b7ar43.js`) that the `/` route loads on first paint.

- Impact: every visitor downloads ~1 MB of export code whether or not they export. On a 3G phone this is several seconds of blocking parse.
- Fix: `next/dynamic` / `await import()` inside `exportInvoice` (page.tsx:1417). Expected saving: ~700 KB off first load.
- Confidence: **measured**, not assumed.

### H1 — Zero `next/dynamic` in the entire project
`grep "dynamic("` across `app/`, `components/`, `lib/` → **0** matches. Nothing is code-split. `LogoCropper` (432 lines, pulls in `lib/image/crop`) is statically imported into `app/page.tsx:12` and `app/account/settings/page.tsx:11` despite rendering conditionally.

### H2 — `app/page.tsx` is a 2,153-line monolith
- `Home()` spans **L201–1815 (~1,615 lines)**.
- **46 `useState`, 16 `useEffect`, 16 `useRef`, 3 `useMemo`, 0 `useCallback`, 0 `React.memo`.**
- Nothing is memoized. `LineCard` (L2030) gets fresh handler identities every render (`updateLine` L876, `removeLine` L877, `advanceFromLine` L916, `saveReusableItem` L1249), so **every line re-renders on every keystroke in any field**.
- Fix: extract hooks/subcomponents, wrap `LineCard` in `memo`, memoize handlers with `useCallback`.
- Confidence: **measured** (hook counts from source).

### H3 — Focus is never restored when any modal/drawer closes
Verified in source: `confirm-dialog.tsx:40–68` moves focus *in* but saves no trigger reference; `invoice-settlement.tsx:138–161` identical. `page.tsx` drawers (`ProfileDrawer`, `SavedLibraryDrawer`, `NoteSaveDialog`, `FinalizeConfirmDialog`) add Escape but no focus trap or restore.

- Impact: keyboard/screen-reader users are dropped to `<body>` after closing. WCAG 2.2 SC 2.4.3.
- Fix: store `document.activeElement` on open, restore on close, trap Tab.

### H4 — Low-contrast text fails WCAG AA
`app/invoices/page.tsx:490` `text-muted-foreground/60`; `app/auth/login/page.tsx:37` and `signup/page.tsx:60` `text-muted-foreground/80`; `row-actions.tsx:21,25` `text-foreground/80`. The base `--muted-foreground` is `#657069` (~4.6:1); the `/60` variant is below 4.5:1. The codebase itself documents this trap at `page.tsx:122` ("/70 measured 1.9:1") yet `/60` and `/80` remain.

### H5 — Logo images bypass optimisation AND are over-downloaded
All three `<Image>` uses (`app/page.tsx:1491,1594`, `app/account/settings/page.tsx:172`) set `unoptimized`. No `sizes=`, no `priority=` anywhere in the project (`grep` → NONE). A user-uploaded logo up to **2 MB** (`MAX_UPLOAD_BYTES`) is stored full-resolution and rendered into a 96–128 px box. The browser downloads the full file.

## 2. Database findings (live Supabase data)

### D1 — `number_reservations` has RLS on but NO policy (security gap)
Advisor `rls_enabled_no_policy` reports it. Root cause found in source: migration `0001:214` created the policy *"workspace members read number reservations"*, and migration `0002:115` **dropped it without a replacement**. Same class as `private.invoice_finalization_requests`.

- Impact: with RLS on and no policy, the table is deny-all for anon/authenticated. It is a latent trap: any future direct read returns empty with no error. Currently masked because access goes through SECURITY DEFINER RPCs — which is exactly why it went unnoticed.
- Fix: either add an explicit policy or document deny-all as intentional; a comment in the migration is the minimum.

### D2 — `workspaces` is seq-scanned 3,720 times for 2 rows
Live `pg_stat_user_tables`: `workspaces` `seq_scan=3720`, `idx_scan=156`; `logo_assets` `seq_scan=437`. `workspaces` has only **2 live rows**, so this is the RLS helper (`current_workspace_id()`) doing a full scan per row-checked. At beta scale it is harmless; the ratio is a signal to watch, and `public.profiles` shows a healthy `idx_scan=3931` for contrast.

### D3 — 17 SECURITY DEFINER functions callable by `authenticated`
Advisor `authenticated_security_definer_function_executable` (count 17). Documented as intentional in `progress.md` (14 app-facing RPCs). **Action:** verify the list still matches the documented set post-`0034` — the count moved from 14 to 17.

### D4 — Unindexed foreign keys (2)

### D5 — 18 unused indexes
All flagged "not used", including the four `logo_assets_*` retention indexes and `invoice_finalization_requests_*`. Expected pre-launch (workers not exercised), but re-check after load.

The question asked was whether mobile view UI/UX is properly responsive. Measured, not assumed — new harnesses in `scripts/`, run against the production build on port 3100.

### Verdict: responsive. One real defect found and fixed.

**What passed, measured:**

| Check | Result |
|---|---|
| Horizontal document overflow | **0px** at 320 / 360 / 390 / 414 / 768 / 1024 |
| Touch targets below the 24px AA floor (SC 2.5.8) | **0** — every control passes |
| Content painted under the fixed bottom dock | **0** across all 6 steps at 320 / 390 / 768 / 1024 / 1100 / 1279 |
| Controls reachable by scrolling past the dock | **16/16** at 320 / 390 / 1024 / 1279 |
| A4 paper on mobile | scales to fit (205px @320, 268px @390), no horizontal scroll |
| Stepper overflow | clipped by its own `overflow-x-auto` box, last step reachable — intentional scroller |
| e2e suite | **57/57 pass** on mobile-320, mobile-375, desktop |

The `lg:pb-10` / `xl:` mismatch looked like a bug — bottom padding drops to 40px at 1024px while the dock is not hidden until 1280px. Measurement showed it is **not** a defect: at the bottom of the scroll there is no content under the dock at any width, and every control can be scrolled clear. The earlier "covered" readings were an artifact of sampling mid-scroll with `scrollTo` called inside the probe; a corrected probe that holds scroll constant and excludes the dock's own buttons reports 0.

**The one real defect — sub-44px touch targets:**

Row actions were 32x32 and the discount controls 32px tall, all under the 44x44 WCAG 2.2 SC 2.5.5 floor, including a *destructive* control (`Remove line`) where a near miss is the expensive kind. Raising the paint to 44px would crowd the row and, at the 320px floor the app supports, push the ledger grid off screen.

Fixed by decoupling the hit area from the painted size — a `.touch-hit` utility in `app/globals.css` grows a transparent `::after` pseudo-element to `max(100%, 44px)` on both axes, inside `@media (pointer: coarse)` so a mouse-driven desktop keeps the original geometry and gains no overlapping dead zones. Applied to the shared row-action token, the compact discount field, the remove-discount button, and the stepper chips. Painted sizes are unchanged.

Verified by hit-testing: all 10 `.touch-hit` controls now resolve to a >=44x44 region (`scripts/audit-touch-hitarea.mjs`), and on a fine pointer the rule does not apply at all (`scripts/audit-touch-scope.mjs` — `::after` content is `none`, targets keep painted size).

**Regression guard:** `tests/unit/touch-target.test.ts` (6 tests). Mutation-tested against six changes — query rewritten to `(min-width: 0px)`, to `(pointer: fine)`, media wrapper removed, `position: relative` → `static`, `44px` → `40px`, and `.touch-hit` dropped from the `page.tsx` token — every one is caught. Two earlier versions of this guard did **not** catch the query rewrite: the first matched the literal string `@media (pointer: coarse)`, and the second read the prose comment naming that query as if it were the condition. Comments are now stripped before parsing, and the condition is asserted directly.

## 10. Signed-in surfaces (2026-10-11, fourth pass) — the guest result did not transfer

Section 9 concluded mobile was responsive. That conclusion was measured on `/` **with no session**, and it was wrong for the signed-in app. The signed-in pages are not the same layout:

| Area | Guest | Signed in |
|---|---|---|
| Header | 1 control | up to 3 (Admin, View history, Sign out) |
| From / Bill to / Notes | 1 action each | 2 each, plus status text |
| Logo | plain file input | dropzone, progress, promote/remove |
| Preview | no Finalize | Finalize button + history note |
| Other routes | do not exist | invoices, customers, trash, settings |

So "0px overflow as a guest" said nothing about the app a signed-in user sees.

### Measurement trap that hid the breakage

Under mobile emulation Chromium **widens the layout viewport to fit overflowing content**. On a 320px device the signed-in `/` reported `window.innerWidth = 691`, so `scrollWidth - clientWidth` was **0** and the page looked clean while being 371px too wide. Every measurement below is taken with emulation off, comparing against the device width rather than `innerWidth`. `scripts/measure-authed.mjs` and `tests/e2e/authed-layout.spec.ts` both carry that note.

### Findings and fixes

| Surface | Before @320px | After | Cause |
|---|---|---|---|
| `/` (signed in) | **371px** | **0** | two separate bugs (below) |
| `/customers` | **126px** | **0** | grid + unbreakable email |
| `/invoices` | 0 | 0 | clean |
| `/invoices/trash` | 0 | 0 | clean |
| `/account/settings` | 0 | 0 | clean |
| `/admin/allowlist` | — | — | **not measurable** (see below) |

**1. `SignOutButton` hardcoded `w-full`.** Correct inside the mobile dropdown, wrong in the invoice header where the button is inline at every width. Below `lg` it demanded 100% of a flex container whose own width its content helped determine, resolving to **318px on a 320px screen**. Fixed by removing the width from the component and letting each call site decide; only the dropdown passes `w-full`. 371 → 148px.

**2. The `Admin` link rendered below `sm` despite `hidden`.** Written as `` `${buttonVariants({...})} hidden sm:inline-flex` `` — a template literal, so no merge. `buttonVariants` already emits a `display` utility, so `hidden` and `inline-flex` both set `display` and the **generated stylesheet order** decided the winner, not the class-attribute order. Measured: `display: flex` at 320px. Wrapping it in `cn()` fixes it (`cn` is a tailwind-merge drop-in; verified it drops the earlier `inline-flex`). 148 → 0px, after also making the header's account controls icon-only below `sm` with `sr-only` labels — 134px of logo plus three labelled controls needs 452px in a 288px box, so the labels were what had to give.

**3. `/customers` grid sized to max-content below `md`.** `md:grid-cols-[...]` with no base column definition, so below 768px the grid fell back to a single `auto` track, which sizes to max-content. Added `grid-cols-1` (Tailwind's `repeat(1, minmax(0, 1fr))`), which is shrinkable.

**4. The customer email could not wrap.** `<p>` with no wrapping control, and an email has no spaces, so it spilled **142px** (`scrollW 344` vs `clientW 202`). Added `break-words`, plus the same on the address line.

### Not measurable without credentials

`/admin/allowlist` is a server component that calls `supabase.auth.getUser()` and a `current_profile_is_admin` RPC **on the server**, then `redirect`s. Route stubbing cannot fake a server-side Supabase call, so it redirects to `/auth/login` and any measurement of it would silently be a measurement of the login page. Excluded from the suite and reported as skipped rather than measured. A real test account would close this.

### Regression guard

`tests/e2e/authed-layout.spec.ts` (3 tests) seeds the session cookie and asserts zero overflow on every signed-in route at 320/390/768px. Design notes that mattered:

- The cookie format was **measured** (`scripts/diagnose-session-storage.mjs`), not assumed: `sb-<ref>-auth-token` = `base64-` + base64url of the session JSON.
- Seeding degrades silently — a format change would render the app as a guest, and a guest layout has no overflow, so the test would pass while testing nothing. `expectSignedIn` asserts the signed-in state per route and fails loudly.
- The signed-in marker differs by route: `/` shows sign-out inline at all widths, but the workspace pages put it in a `lg:flex` nav or a closed `<details>`, so at 320–768px it is not in the accessibility tree. Those pages assert the **absence** of the "Sign in to continue" gate instead.
- It runs once, in the desktop project. Mobile projects use `isMobile: true`, which is the emulation that masks the very overflow being tested.
- Mutation-tested: reintroducing `w-full` and reintroducing the template-literal `hidden` each make it fail, naming the offending element.

Driving the login form was tried first and abandoned: it failed 2 of 9 runs even single-threaded, and 9 of 9 under parallel load.

**Validation after pass 4:** `tsc` clean · lint clean · **170/170 unit** · **60 passed / 6 skipped / 0 failed e2e**, three consecutive runs.

## 11. Mobile UI/UX and a silent data bug (2026-10-12, fifth pass)

### A decimal price could not be saved, and nothing said so

The price field asked for a decimal (`step="any"`, `inputMode="decimal"`, so a phone shows a decimal keypad), the form considered itself complete, and the preview rounded the result — but money is whole taka end to end: the columns are `bigint`, `formatMoney` rounds, and the server schema requires `z.number().int()` for `quantity`, `unitPrice` and `discountValue`. A decimal therefore failed validation at the API, and the client discarded the server's message, showing only **"Not saved"**.

Reproduced end to end: price `10.5` → preview ৳11 → server 400 → "Not saved"; price `1050` → 200 → "Saved".

Fixed: the field asks for an integer; a decimal in any of the three numeric fields marks the form incomplete and names the problem at export and finalize; and a failed autosave now surfaces the server's reason. The field keeps what was typed rather than silently rounding it, matching the rule the payment dialog already follows ("silently altering an amount someone is about to record as money received is not acceptable").

### The logo cropper was unusable on a short phone

At **320×568** the cropper could be neither confirmed nor dismissed. The panel capped at `94vh` (534px) while its content needed 598px, with `overflow-hidden` and **no scrollable ancestor anywhere above it**. Cancel sat at y=577 and "Use this crop" at y=529–569 — both outside a 568px viewport. It fits at 390×844, which is why every existing check passed.

Fixed with three changes: the panel scrolls, the crop stage is `38vh` instead of `46vh`, and the action row is sticky. Measured after: both actions inside the viewport.

### Other mobile changes

- The editor header now collapses its account controls into the same `<details>` menu the workspace pages use, so the earlier icon-only workaround is gone.
- The history filter panel was five stacked full-width rows, **270px** on a 390px screen — 52% of the viewport before the first invoice. Now a two-column grid: **174px**, three rows. The "More" toggle also grew to 44px.
- Sort labels were trimmed so the closed select stops truncating to "Newest issu".

### Confirmed but NOT yet fixed

- **The step bar does not follow the active step.** `goToStep` (page.tsx:282) calls `window.scrollTo` but never scrolls the `<ol>`, so after tapping Next the highlighted chip can sit off-screen. There is also no edge affordance to show the row scrolls.
- **Many controls are still under the 44px target.** `size="sm"` is `h-8` (32px) with no mobile override: the "Load saved customers"/"Save customer" pair, notes actions, Prev/Next, "Reset view", the "Past due" tile, "Clear filters"/"Try again", the payment-ledger Remove, and the auth-page links (16–20px tall). These pass the 24px AA floor but not the 44px AAA target the rest of the app now meets.

### Sub-agent reviews

**Security — no high-severity findings.** RLS is enabled on all 15 tables with no `using (true)` anywhere; every `SECURITY DEFINER` RPC re-validates `auth.uid()` and re-scopes by `workspace_id`; trigger helpers are revoked from `anon`/`authenticated`; every body-reading route validates with zod first; no raw SQL; no `dangerouslySetInnerHTML`; the logo upload validates size, MIME **and** magic bytes and builds the storage path server-side. Three low findings: `seller_profiles.logo_asset_id` is not constrained to the same workspace (bounded — `logo_assets` RLS blocks the read); the same-origin check covers only the admin routes (residual risk low, `SameSite=Lax` plus a JSON content-type requirement); and there is no rate limiting on payment recording or uploads.

**Performance — two high findings.** (1) **No pagination anywhere**: `/api/invoices` and `/api/customers` select unbounded, and the client renders every row. (2) **Filter, search and sort run in JavaScript after a full fetch**, so narrowing the view never reduces database load. Also: `LineCard` is not memoized and `updateLine` is recreated every render, so a keystroke re-renders the 2144-line tree; and a `ResizeObserver` effect depends on `lines`/`discount`/`subtotal`/`total`, re-measuring every row on every keystroke. Missing indexes on `lifecycle_status`, `due_date` and `customers.updated_at`.
